# 城市宠物医院 · 疫苗接种与术后回访平台

Vue 3 + Element Plus 前端、Node.js (Express) 后端、PostgreSQL 数据库，单镜像多阶段构建、`docker compose up -d` 一键部署。

平台以 **「统一病例」** 为核心：前台、医生、护士、药房、主人围绕同一病例协作；线上图文咨询、到院检查、现场医嘱、术后照片、回访结果全部进入同一条病例时间线并沉淀为宠物长期档案。

---

## 原始需求

> 建设城市宠物医院疫苗接种与术后回访平台，可采用 Vue 3、Spring Boot 和 PostgreSQL。宠物主人为猫狗建档时，平台记录品种、年龄、体重、绝育状态、过敏史、既往疫苗、驱虫、慢病和主人联系方式。预约疫苗或手术时，平台根据医生排班、诊室、疫苗批号、术前检查、禁食要求和宠物应激程度生成到院计划。到院后，前台核验宠物身份、主人授权和费用，护士记录体温、体重、精神状态和是否适合接种或麻醉。若疫苗缺货、宠物发热、主人临时改约、术前检查异常、术后伤口渗血、用药不配合或主人投诉收费，平台要把前台、医生、护士、药房和主人放在同一病例中处理。接种或手术完成后，疫苗批号、医嘱、用药、术后照片、复诊时间、回访结果和异常反馈进入宠物长期档案，用于下一针提醒、传染病排查和医院质量复盘。平台还要覆盖宠物走失、住院笼位、术后伊丽莎白圈、疫苗冷链、主人代办和跨院转诊，让病例记录能支持医院内部协作和主人长期信任。若宠物主人通过线上问诊补充病情，平台要把图文咨询、到院检查和现场医嘱合并到同一病例，避免医生重复询问。

## 一键启动（宿主 docker compose）

```bash
cp .env.example .env        # CC_PUBLISH_PORT 为宿主机发布端口，默认 3059
docker compose up -d --build
```

查看健康状态与实际映射端口：

```bash
docker compose ps
docker compose port app 3000     # 形如 0.0.0.0:3059
```

浏览器访问：**http://host.docker.internal:3059**（端口以 `docker compose port app 3000` 的实际输出为准）。

- 数据库 PostgreSQL 仅在 compose 内网通过服务名 `db` 访问，**不发布到宿主**；应用端口通过 `${CC_PUBLISH_PORT}:3000` 发布。
- 容器首次启动自动建表；当 `users` 表为空时自动灌入演示种子数据（重复启动不会覆盖数据）。
- 停止并清理：`docker compose down`（保留数据加卷清理用 `docker compose down -v`）。

健康检查：容器内置 `HEALTHCHECK` 访问 `/api/health`；`docker compose ps` 中 app 与 db 均应为 healthy。

## 技术结构

```
.
├── docker-compose.yml          # app + postgres，仅发布 app 端口
├── Dockerfile                  # 三阶段：前端构建 → 后端依赖 → 非 root 运行镜像（含 HEALTHCHECK）
├── .env.example
├── backend/
│   ├── db/schema.sql           # 统一病例模型：cases + case_events 时间线
│   ├── db/seed.js              # 演示数据
│   ├── db/init.js              # 等待数据库→建表→首次种子
│   └── src/                    # Express 路由：auth/pets/resources/cases/staff
└── frontend/                   # Vue 3 + Vite + Element Plus（构建产物由后端同源托管）
```

关键设计：所有角色动作（预约、计划、核验、分诊、术前检查、接种、手术、医嘱、发药、住院、伤口巡查、回访、照片、问诊、转诊、投诉、收费）都写入 `case_events` 统一时间线；接种批号、医嘱、用药、回访结果同步进入 `pets` 长期档案并生成 `reminders`。
